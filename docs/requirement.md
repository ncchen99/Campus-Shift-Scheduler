下面我把你的描述整理成一份「可直接丟給同學/自己開發用」的需求文件（PRD + 技術規格），並把用 **Google Apps Script（GAS）+ Google Sheets + Web App（HTML Service）** 的實作方式拆成可落地的步驟。

---

## 1) 專案目標與使用情境

### 目標

把「每月收集大家沒空時間 → 班長手動整理 Excel → 排班」流程，變成：

* 一般同學：登入後用月曆大表格勾選「沒空」＋填特殊需求
* 班長：登入後除了填自己的沒空，也能在排班頁用下拉選人快速排班；並支援「同一天自動補齊同人」以加速

### 角色

* **一般使用者（工讀生）**

  * 只能編輯自己的「沒空時間」與「特殊需求」
  * 可以查看（可選）自己送出的紀錄
* **班長（管理者）**

  * 可查看所有人的沒空時間與需求
  * 可在排班頁編輯整個月班表（指派人員到每個班段）
  * 享有「同日自動補齊」的排班加速功能
  * 可匯出/產出最終班表（Sheet / CSV / PDF 可選）

## 2) 功能需求（PRD）

### A. 共用：登入與權限

1. 系統提供登入入口：

   * 一般使用者：用 Google 帳號登入（建議以學校帳號為主）
   * 班長：額外提供「班長入口」與班長密碼（簡化即可）
2. 權限規則：

   * 一般使用者不可看到他人特殊需求與沒空細節（除非你想開放透明）
   * 班長可看到全部

> 建議做法：
>
> * **一般登入用 Google OAuth（GAS 的 Session 取得 email）**
> * 班長用「同一個 Google 帳號 + 角色表」或「班長密碼」二選一
> * 你說想要「寫死帳密只有班長用」也可行，但要注意：GAS 不是為帳密登入設計的，通常會用「班長密碼」當第二道門（簡單好用）

---

### B. 一般使用者頁：填寫沒空時間（Availability）

#### B1. 月曆大表格

* 顯示當月日曆式表格
* 每天列出該日的班段（由後台班段設定表動態生成）
* 使用者只需要勾選「沒空」的格子（預期很少）
* 支援：

  * 一鍵清空本月勾選
  * 顯示已勾選的狀態（再次登入仍保留）

#### B2. 特殊需求輸入

* 提供一個欄位（textarea）讓使用者輸入偏好/限制（純文字，人工判斷）

  * 例如：希望連續時段、偏好六日、某幾天可連上、每週最多幾班…等
* 送出時與沒空資料一起保存
* 後續可在班長排班介面顯示

#### B3. 送出流程

* 使用者按「儲存」→ 系統寫入資料庫（Sheet）
* 顯示成功提示、最後更新時間

---

### C. 班長頁：排班（Roster Scheduling）

#### C1. 排班大表格

* 同樣是月曆大表格，但每個班段格子是「指派人員」而非勾選沒空
* 點擊格子 → 出現下拉式選單（當日/該班段可上班的候選名單）

候選名單生成規則（基礎版）：

* 排除：該使用者在該日該班段「沒空」
* 其他條件（可擴充）：本月已排班數、連班偏好、避免連續天數…先不做也行

#### C2. 同日自動補齊（你要的加速功能）

* 當班長在同一天的第一個班段選了「A」：

  * 系統自動把同一天其他班段也填入 A（或依規則填入）
* 需提供開關/策略（避免班長想不同人）

  * 策略建議：

    1. **自動填滿同一天所有班段**
    2. **只填下一個班段**
    3. **詢問/提示可一鍵套用到同日**
  * MVP 建議：做「填完第一格後，右上角跳出：是否套用到同日？」最不會打擾，也不會誤填太多

#### C3. 顯示特殊需求（側欄/彈出）

* 排班頁右側（或可折疊 Drawer）顯示每位使用者的特殊需求：

  * 列表：人名 + 需求摘要
  * 點人名展開完整內容
* 排班時點選某位同學，可在側欄自動定位到該同學需求（加速人工判斷）

#### C4. 匯出/發布（可選，但很實用）

* 一鍵產出：

  * 班表 Sheet（適合列印）
  * CSV（給班長下載）
  * 或以 Google Calendar / LINE 通知（進階版再做）

## 3) 後台可配置需求（班段規則）

### 班段規則（Shift Rules）

* 平日（一～五）：

  * 17:00–21:00（4h）
  * 21:00–24:00（3h）
* 假日（六日）：

  * 08:00–12:00
  * 12:00–16:00
  * 16:00–20:00
  * 20:00–24:00

需求：**班段不是寫死在程式，而是由設定表決定**
因此 UI 的「月曆表格」會依照當天是平日或假日，自動產生對應班段列。

## 5) 系統流程（使用者故事）

### 使用者（工讀生）

1. 開啟網址 → 自動取得登入 email
2. 選擇月份（預設當月）
3. 系統生成當月日曆班段表
4. 勾選沒空 + 填特殊需求
5. 按儲存 → 寫入 `Unavailability` + `SpecialRequests`

### 班長

1. 開啟網址 → 判斷 role=leader（或輸入班長密碼）
2. 進入「排班」分頁
3. 看到同一份月曆班段表，但格子可選人
4. 點格子 → 下拉選單顯示可上人選
5. 選 A →（依設定）自動套用同日其他班段
6. 右側看到大家特殊需求，輔助人工決策
7. 完成後按「匯出/發布」

## 6) 用 Google Apps Script 怎麼做（落地步驟）

### Step 0：建立 Spreadsheet

* 建立 Google Sheet：例如 `ActivityCenterSchedulerDB`
* 建好以上工作表：Users / ShiftRules / Unavailability / SpecialRequests / Roster
* 先把使用者名單與班長 role 填好
* ShiftRules 先填入你的平日/假日規則

### Step 1：建立 Apps Script 專案

* 在該 Spreadsheet：`擴充功能 Extensions → Apps Script`
* 專案結構建議：

  * `Code.gs`（入口、路由）
  * `db.gs`（讀寫 Sheet 的 helper）
  * `auth.gs`（角色判斷）
  * `shifts.gs`（根據月份生成當月班段）
  * `availability.gs`（沒空讀寫）
  * `roster.gs`（排班讀寫、候選人計算）
  * `ui.html` + `ui.js` + `ui.css`（前端）

### Step 2：做成 Web App（HTML Service）

* `doGet(e)` 回傳 HTML 頁面
* 前端用 `google.script.run` 呼叫後端 API

你會需要的後端 API（建議最少就這些）：

1. `getMe()` → 回傳目前登入 email、role、name
2. `getMonthModel(month)` → 回傳該月所有日期 + 每日班段（由 ShiftRules 算出）
3. `getMyUnavailability(month)` → 回傳我已勾選的沒空
4. `saveMyUnavailability(month, selections, specialText)` → 寫入 Unavailability + SpecialRequests
5. `getAllSpecialRequests(month)`（班長）→ 取得所有人的特殊需求
6. `getCandidates(date, ruleId)`（班長）→ 回傳可上人選（排除沒空）
7. `setRosterCell(month, date, ruleId, userId, options)`（班長）→ 寫入 roster，並依 options 執行「同日自動補齊」

### Step 3：實作「同日自動補齊」邏輯

在 `setRosterCell` 裡：

* 寫入指定格
* 若開啟 autoFillSameDay：

  * 取得該日所有 ruleId
  * 對尚未指派的班段（或全部）填入同一 userId
  * 注意：不要覆蓋班長已經手動填的（除非選擇強制覆蓋）

前端交互建議（避免誤填）：

* 班長選人後，彈一個小提示：

  * ✅「套用到同一天所有班段」
  * ⭕「只填這一格」
    -（記住我的選擇）

### Step 4：部署

* Apps Script → `部署 Deploy → 新增部署 New deployment → Web app`
* 設定：

  * Execute as：**Me（你）**
  * Who has access：

    * 若都用學校帳號：選 **Anyone within domain**
    * 若混雜私人帳號：選 **Anyone with the link** + 前端再用 Users 白名單擋
* 部署後拿到網址就是入口

## F1：班長排班頁新增「已排班工時統計」側欄

### 目的

班長在排班時能即時看到每位同學本月已排班的**時數與班數**，用來平衡分配。

### 顯示位置

* 班長排班頁右側（與「特殊需求」同一個側欄區塊）
* 側欄可切換 Tab：

  * Tab A：特殊需求
  * Tab B：工時統計（或合併顯示：每個人一列，右側有需求 icon 可展開）

### 欄位內容

每位使用者顯示：

* 姓名
* 本月 **已排班總時數**
* 本月 **已排班班數**
* 近 7 天/本週時數（可選，進階）
* 警示狀態（可選）：

  * 低於最低時數（藍色）
  * 超過上限（紅色）
  * 連續天數過多（橘色）

### 計算規則（MVP）

* 工時由 `ShiftRules` 的每個班段 `start/end` 算出（含跨日 21:00–24:00 這種）
* 工時計算只依據 `Roster` 中已指派的人
* 若班長選人時啟用「同日自動補齊」，要在寫入後即刻更新工時

### 需要的 API（新增）

* `getMonthlyWorkload(month)`（leader only）

  * 回傳 `{ userId: {hours, shiftsCount, ...} }`
* `recalcMonthlyWorkload(month)`（可選）

  * 用於修復/重新計算（例如大量修改後）

* 系統取得登入者 email（GAS `Session.getActiveUser().getEmail()`）

### 需要的 API（新增）

# 你圖片的班表格式判斷（可實作規格）

## 版面結構

1. **欄（Columns）以「日期」為主**

   * 每天佔用固定的欄數：

     * 平日：2 欄（17–21、21–24）
     * 假日：4 欄（8–12、12–16、16–20、20–24）
2. **列（Rows）以「資訊層級」為主**
   你圖中每一週是一個區塊，並且有固定的資訊列（大概像這樣）：

   * 上方 Header：顯示班段長度（例如 4、3）＋班段時間（17-21 / 21-24…）
   * 每週開始會有一列「日期」顯示（12月1日、12月2日…）
   * 每天的排班內容落在同一列/或同一組列中
   * 有一些固定的左側欄（你圖左邊有「日期 / 值日區段 / 公佈值班 / 公佈結束」這類標籤）

> 你實際要不要保留那些左側「標籤列」取決於你們現在班表習慣；
> 但**最核心**是：以天為單位的多欄班段 + 合併儲存格 + 顏色。

## 顏色規則

* **同一個人固定一個底色**（整個月一致）
* 顏色用來快速辨識：誰上了哪些班、同一天是不是同人

## 合併儲存格規則（你特別要求）

* 若同一人同一天連續班段（例如平日兩班都同人），則**合併同一天的多欄格子**成一格
* 假日同人連續兩段/三段/四段，也都應該合併成一格
* 合併後格子內容顯示姓名一次即可（更好讀）

## 視覺排版細節（建議）

* 週與週之間可加粗邊框或空白分隔
* Header 背景淡色（你圖是綠色系）
* 內容區每格置中、字體大小一致
* 凍結最上方 Header 列、以及左側標籤欄（方便捲動）

# 匯出功能規格（你要的）

## 匯出目標

* 方式 A：匯出成「新的 Google Spreadsheet」（推薦，格式最好控制）
* 方式 B：匯出成 Excel `.xlsx` 檔（可行，但 GAS 這邊通常是：先建立 Google Sheet → 再用轉檔輸出 xlsx）

## 匯出內容

* 指定月份班表（依 `Roster`）
* 套用：

  * 班段 header（時間、時數）
  * 每人顏色
  * 合併連續班段
  * 週區塊邊框
  * 產出後檔名：`活動中心排班_YYYY-MM`

## 需要的資料來源

* `ShiftRules`：決定每日班段欄數、每段時間、每段時數
* `Roster`：每格 assignedUserId
* `Users`：顯示姓名
* `ColorMap`（新增）：每位使用者對應色碼（固定）

### 新增 Sheet：`ColorMap`

> 顏色可以第一次自動生成並寫入 ColorMap，之後固定使用，達成「每人固定顏色」。

## 匯出按鈕（班長介面）

* `匯出 Google Sheet`
* `匯出 Excel`

按下後：

* 顯示「已建立檔案」並回傳連結（Google Sheet 連結）
